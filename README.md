# RAG 混合检索问答系统

> 基于 BM25 + 向量混合检索（RRF 融合）与 Cross-Encoder 重排的检索增强问答系统。
> 状态：**整理中**（代码与评测脚本正在陆续归档，README 先行）

## 概览

完整的 RAG 链路，从文档解析到流式问答与引用溯源：

- **入库**：PDF / Word / Markdown 多格式解析 → 按标题层级切分并控制重叠 → 向量化写入 Chroma
- **检索**：BM25 与向量检索并行召回 → RRF 融合 → Top-50 交给 Cross-Encoder 重排
- **生成**：SSE 流式输出，回传命中片段支撑引用溯源
- **会话**：MySQL 存储会话 / 消息表，支撑多轮上下文与回溯

规模实测：约 3k 篇文档 / 3 万 chunk。

## 为什么做混合检索

纯向量检索在专业术语、专有名词、精确关键词场景下召回不足——语义泛化是优点，但在"必须字面命中"的查询上就是短板。因此引入 BM25 与向量双路召回，用 RRF 做排名融合，再交 Cross-Encoder 精排，兼顾语义泛化与字面匹配。

## 效果与延迟

自建 120 条人工标注评测集，Recall@K / MRR 自动化回归，对比三组配置：

| 指标 | 优化前 | 优化后 |
| --- | --- | --- |
| Recall@5 | 65% | 88% |
| p95 延迟 | 210 ms | 260 ms（重排未优化时 380 ms）|
| 引用准确率（人工抽检）| — | 92% |

延迟压回的手段：Top-50 截断、重排 batch 化、chunk 预取。每次策略调整都记录效果与延迟的取舍，避免只看效果单边决策。
